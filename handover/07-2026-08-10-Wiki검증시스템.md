# 2026-08-10 Wiki 검증 시스템 구축

## 📌 세션 목표
Wiki 적재 이후 검증을 2가지 관점에서 수행하는 시스템 구축
1. 기계 검증: Frontmatter, 파일명, 스키마 구조
2. 컨텐츠 검증: LLM 리뷰 (내용 일치도, 누락, 임의 생성)

---

## 🎯 배경: 왜 검증이 필요한가?

### 문제점 발견사항 (이전 세션)
1. **Raw와 Wiki의 불일치** → 어떻게 동기화할 것인가?
2. **액션 추적의 어려움** → "조용히 사라지는" 액션 감지 필요
3. **수동 Wiki 생성의 오류** → 임의 생성 또는 누락 가능성

### 검증의 중요성
```
Raw (SSOT) ✓ 정확
    ↓ (Ingest 스킬)
Wiki (파생) ? 정확한가?
    ↓ (검증 시스템)
검증됨 ✓
```

## ✅ 완료된 작업

### 1. 기계 검증 스크립트 (validate-wiki.js)

**위치**: `C:\20260810\validate-wiki.js`

**검증 항목**:
1. **파일명 규칙**
   - 패턴: `YYYY-MM-DD-*.md`
   - 예: `2026-06-11-제품주간회의.md` ✓

2. **Frontmatter 필드**
   - 필수: `원본`, `회의일`, `회의체`, `참석`
   - 선택: `wiki_생성`, `마지막_업데이트`

3. **스키마 구조**
   - 필수: `## 🎯 결정` 섹션
   - 필수: `## ✅ 액션` 섹션
   - 필수: `## ✔️ 완료된 액션` 섹션
   - 필수: `## ⏸️ 미해결 액션` 섹션
   - 액션 테이블: 올바른 컬럼 구조

4. **일관성 검증**
   - 파일명의 날짜 vs Frontmatter의 회의일 일치

**사용 방법**:
```bash
node validate-wiki.js
```

**출력 형식**:
```
✅ 파일명: 통과/실패
❌ 오류 (N개): 상세 오류 메시지
⚠️  경고 (N개): 권장사항
```

### 2. 컨텐츠 검증 LLM 스킬 (wiki-content-review)

**위치**: `.claude/skills/wiki-content-review/SKILL.md`

**검증 관점**:

#### 2-1. 내용 일치도
- Wiki의 결정사항이 Raw의 `### 결정` 섹션과 일치?
- Wiki의 액션이 Raw의 `## 액션 아이템`과 일치?

#### 2-2. 임의 생성 감지
- Raw에 없는데 Wiki에만 있는 내용?
- 예: "박준서는 이것을 매우 중요하게 생각한다" (Raw에는 단순히 "필요하다"고만 기록)

#### 2-3. 누락 확인
- Raw의 중요 결정이 Wiki에 빠졌는가?
- Raw의 액션이 Wiki에서 누락?
- 수치(42% 이탈 등)가 정확하게 포함?

#### 2-4. 액션 상태 추적
- **열림 → 진행 중 → 완료**: 상태 변화 기록?
- **조용히 사라짐**: 마감 지난 액션이 Raw에서 업데이트 안 됨?
  ```
  Raw (2026-04-30): [ ] 강태우 - 액션
  Raw (2026-05-14): (언급 없음) ← 경고!
  ```
- **이전 액션 추적**: "완료된 액션", "미해결 액션" 섹션이 Raw와 일치?

#### 2-5. 의존성 표시
- 외부 블로커(🔴)가 정확히 표시? (A사 응답 대기 등)
- 내부 의존성(🟢)이 정확히 표시? (다른 액션 완료 필수)
- 블로커(⚫)가 진행 불가 상태를 의미?

#### 2-6. 고위험 액션
- 🚨 표시가 정확한가? (후속 액션의 선행조건)
- 반복되는 지연/패턴이 분석되었는가?

**사용 방법**:
```bash
/wiki-content-review wiki/2026-06-11-제품주간회의.md
/wiki-content-review all
/wiki-content-review wiki/2026-06-11-제품주간회의.md --verbose
```

**출력 형식**:
```
✅ 기본 검증 (파일/내용 일치)
✅ 결정사항 검증 (3개)
✅ 액션 추적 (4개)
⚠️  미해결 액션 추적 (경고)
✅ 의존성 표시
✅ 고위험 표시

📊 결과:
  통과: Yes
  오류: 0개
  경고: 1개
  평가: ✅ 양호
```

## 🚨 발견될 가능성이 높은 문제점

### 1. 액션 추적 누락
```
Raw (이전): [ ] 액션 A
Raw (현재): (언급 없음)
→ 경고: "조용히 사라진" 액션
```

### 2. 임의 생성 콘텐츠
```
Raw: "A/B 테스트 진행 결정"
Wiki: "A/B 테스트 예상 결과: 25% 감소"
→ 오류: 결과는 아직 안 나왔음
```

### 3. 외부 의존성 미표시
```
Raw: "A사에 요청했는데 아직 답변 없음"
Wiki: [ ] 액션 (의존성 표시 없음)
→ 경고: 🔴 A사 응답 대기 표시 필수
```

### 4. 보류 항목 불명확
```
Raw: "정산 주기 보류"
Wiki: ⏸️ 보류 (해결 조건 미기록)
→ 경고: 해결 조건이 명확해야 함
```

## 💡 핵심 인사이트

### 1. 검증의 2가지 관점
- **기계 검증** (스크립트): 빠르고 객관적, 형식만 확인
- **컨텐츠 검증** (LLM): 느리지만 깊이 있는, 의미 검증

### 2. 액션 추적의 중요성
```
가장 흔한 오류: 액션이 조용히 사라짐

Raw (2026-04-16): [ ] 액션 A
Raw (2026-05-14): ← 언급 없음 (상태 불명)
Raw (2026-06-11): ← 언급 없음 (누락?)

해결책: 모든 Raw에 "이전 액션 상태 업데이트" 섹션 필수
```

### 3. 의존성의 명시성
```
"A사에서 답변을 못 줬다" (Raw)
↓
🔴 A사 담당부서 응답 대기 (Wiki에서 명시)
↓
리스크 관리 가능
```
