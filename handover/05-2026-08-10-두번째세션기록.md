## 🚨 발견된 4가지 주요 문제점

### 1. 액션 상태 추적의 불일치 ❌

**상황:**
```
첫 번째 Wiki (2026-04-16):
  박준서 - PG사 3곳 비교표 작성 [열림] (마감: 4/23)

두 번째 Raw (2026-05-14):
  [x] 박준서 - PG사 비교표 (완료)
```

**문제:**
- Raw에서는 체크박스로 상태 업데이트 ([ ] → [x])
- Wiki에서는 이전 회의 액션들이 어떻게 업데이트되는가?
- 각 Wiki 페이지가 독립적이면 이력 추적이 불가능

**현재 체계의 한계:**
- 1차 설계 원칙: "액션 상태는 후속 회의에서만 변경"
- 구현 방식: 정의되지 않음
- 필요: Wiki 동기화 프로세스 (자동? 수동? LLM?)

### 2. 이전 액션의 누락 ⚠️

**상황:**
```
첫 번째 (4/16):
  - 강태우 - PG사 계약 조건 확인, 특히 최소 거래액 (~4/30)

두 번째 (5/14):
  (기록 없음)
```

**문제:**
- 마감일 4/30이 지났는데 Raw에 상태가 기록되지 않음
- 완료? 진행? 홀드? → 불명확
- Raw가 SSOT이므로 모든 상태 변화를 기록해야 함

**영향:**
- Wiki에서도 추적 불가능
- 액션 생명주기 관리 어려움

### 3. 우선순위 변경 사유 기록 부족 📋

**상황:**
```
첫 번째 (4/16):
  "온보딩 개선, 대시보드 개편은 후순위로 미룸"

두 번째 (5/14):
  "신규 가입자 온보딩에서 이탈이 심하다는 CS 피드백"
  → 온보딩 구간별 이탈률 분석 시작
```

**문제:**
- 우선순위가 변경된 이유가 Raw에 명시됨 (CS 피드백)
- 하지만 의사결정 배경이 불명확
- "심하다"의 기준? 고객 영향도? 비용? → 기록 부족

**영향:**
- 향후 같은 결정을 할 때 참고 데이터 부족
- 패턴 분석 어려움

### 4. 외부 의존성 미표시 🔴

**상황:**
```
첫 번째 (4/16):
  "5월 말까지 연동 완료" ← 목표

두 번째 (5/14):
  "스펙 문서가 있어야 착수가 되는데 아직 못 받음"
  "A사에 요청했더니 담당자 응답이 느림. 3일째 회신 없음"
  → "6월 중순으로 미루자"
```

**문제:**
- 연기 사유가 "우리 팀"의 책임이 아님 (A사의 늦은 응답)
- Raw에 "스펙 문서", "담당자 응답 없음"으로만 기록
- 액션 테이블에는 이 의존성이 표시되지 않음

**영향:**
- 액션 지연의 사유를 구분하기 어려움 (내부 지연 vs 외부 블로커)
- 리스크 관리 어려움

## 💡 개선 제안

### 1. Wiki 구조 개선: 의존성 컬럼 추가

**현재:**
```markdown
| # | 담당자 | 항목 | 마감 | 상태 |
| 1 | 박준서 | A사 스펙 확보 | 5/21 | 열림 |
```

**개선안:**
```markdown
| # | 담당자 | 항목 | 마감 | 상태 | 의존성 |
| 1 | 박준서 | A사 스펙 확보 | 5/21 | 열림 | 🔴 A사 응답 대기 |
```

**블로커 표시 규약:**
- 🟢 내부 의존성 (다른 액션 완료 필요)
- 🔴 외부 의존성 (A사 응답, 결정 대기 등)
- ⚫ 블로커 (진행 불가 상태)

### 2. Raw 기록 개선: 이전 액션 상태 업데이트 섹션

**제안 구조:**
```markdown
# 2026-05-14 제품 주간회의

## 이전 액션 상태 업데이트
- [x] 박준서 - PG사 3곳 비교표 작성 (~4/23)
- ⏳ 강태우 - PG사 계약 조건 확인 (~4/30) → 진행 중
- ⏸️ 최민아 - Q3 대시보드 스펙 초안 (~5/7) → 홀드 (온보딩 우선)

## 이번 회의 내용
...
```

### 3. 우선순위 변경 기록 개선

**현재:**
```markdown
## 온보딩 이탈 문제 (신규 안건)
- 최민아: 신규 가입자 온보딩에서 이탈이 심하다는 CS 피드백
```

**개선안:**
```markdown

- **발견**: CS 피드백으로 신규 가입자 이탈 심각성 파악
- **영향도**: 정확한 이탈률 미파악 (구간별 분석 필요)
- **우선순위 변경**: 로드맵상 후순위 → 데이터 분석 필요
- **결정**: 온보딩 이탈률 분석 진행 (Q3 대시보드는 일시 홀드)
```

### 4. 고위험 액션 표시

**현재:**
```markdown
| 1 | 박준서 | A사 연동 스펙 문서 확보 | 5/21 | 열림 |
```

**개선안:**
```markdown
| 1 | 박준서 | A사 연동 스펙 문서 확보 🚨 | 5/21 | 열림 | 🔴 A사 응답 |
```

**표시 기준:**
- 🚨: 후속 액션의 선행조건 (결제 연동 착수 필수)
- 이 액션이 지연되면 전체 일정에 미치는 영향도 표시
