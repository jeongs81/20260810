## 📋 정의된 규칙 요약

### ✅ Raw 회의록 작성 규칙

#### 필수 사항
1. **프론트매터 포함**
   ```yaml
   회의일: YYYY-MM-DD
   참석: [이름(역할), ...]
   ```

2. **파일명 규약**
   ```
   YYYY-MM-DD-[회의체명].md
   ```

3. **결정을 명시적으로 기록**
   ```markdown
   ### 결정
   - **항목**: 구체적인 결정 내용
   ```

4. **액션을 체크박스로 기록**
   ```markdown
   - [ ] 담당자 — 항목 (~마감)
   - [x] 담당자 — 항목 (완료)
   ```

#### 중요: 이전 액션 추적 ⚠️
```markdown
## 이전 액션 상태 업데이트
- [x] 박준서 - 항목 (완료)
- ⏳ 강태우 - 항목 (진행 중)
- ⏸️ 최민아 - 항목 (홀드)
```

**이유**: 없으면 Wiki에서 액션 추적 불가능

#### 필요한 배경 정보
5. **우선순위 변경 시 사유 명시**
6. **외부 의존성 표시** (A사 응답 대기 등)
7. **보류 항목의 조건 기록** (해결 조건 명시)
8. **신규 안건의 발견 배경 기록**

### 📖 Wiki 생성 규칙

#### 필수 구조
1. **프론트매터에 원본 출처 명시**
   ```yaml
   원본: raw/YYYY-MM-DD-...md
   회의일: YYYY-MM-DD
   ```

2. **3계층 구조 유지**
   ```
   🎯 결정 (Decision)
   ✅ 액션 (Action)
   ⏸️ 보류 (Pending)
   ```

#### 액션 테이블 작성
3. **의존성 컬럼 포함**
   ```markdown
   | 담당자 | 항목 | 마감 | 상태 | 의존성 |
   | 박준서 | 스펙 확보 | 5/21 | 열림 | 🔴 A사 응답 |
   ```

   **의존성 표시**:
   - 🟢: 내부 의존성
   - 🔴: 외부 의존성
   - ⚫: 블로커

4. **고위험 액션에 🚨 표시**
   ```markdown
   | 박준서 | A사 스펙 확보 🚨 |
   ```

#### 이력 관리
5. **완료된 액션과 미해결 액션 분리**
   ```markdown
   ## ✔️ 완료된 액션 (이전 회의)
   ## ⏸️ 미해결 액션 (이전 회의)
   ```

#### 결정 작성
6. **결정에 근거와 위험 요소 포함**
   ```markdown
   - **결정**: A사 선정
   - **근거**: 수수료 2.2% (가장 저렴)
   - **위험**: 응답 느림
   - **이전 상태**: 미정 → 확정
   ```

#### 참고 정보
7. **다음 회의 예상 안건 기록**

## 🎯 가장 중요한 2가지 규칙

### 1. 이전 액션의 상태를 항상 업데이트 (Raw)
```markdown
# 새 회의 시작
↓
## 이전 액션 상태 업데이트 (필수!)
- [x] 완료된 액션
- ⏳ 진행 중인 액션
- ⏸️ 홀드된 액션
```

**없으면**: Wiki에서 액션 추적 불가능 → 프로젝트 이력 손상

### 2. 이전 액션을 Wiki에서도 추적 (Wiki)
```markdown
## ✔️ 완료된 액션 (이전 회의)
## ⏸️ 미해결 액션 (이전 회의)
```

**없으면**: 액션 생명주기 관리 불가능 → 진행 상황 파악 어려움

## 📝 규칙 정의 과정

### 발견사항 → 규칙 변환

**문제 1: 액션 상태 추적 불일치**
```
Raw (2026-05-14):    [x] 박준서 - 비교표 (완료)
Wiki (2026-04-16):   박준서 - 비교표 [열림]
                     ↑ 동기화 불가능
```

→ **규칙**: Raw에서 반드시 이전 액션 상태 업데이트

**문제 2: 이전 액션의 누락**
```
Raw (2026-04-16): 강태우 - 계약 조건 확인 (~4/30)
Raw (2026-05-14): (기록 없음)
                  ↑ 추적 불가능
```

→ **규칙**: 모든 이전 액션의 상태를 기록 (완료/진행/홀드)

**문제 3: 우선순위 변경 사유**
```
"온보딩 개선은 후순위" (4/16)
→ "온보딩 이탈 분석" (5/14)
  (이유: CS 피드백)
  ↑ 의사결정 배경 추적 필요
```

→ **규칙**: 우선순위 변경 시 사유 명시

**문제 4: 외부 의존성 미표시**
```
"5월 말 완료" → "6월 중순으로 연기"
(이유: A사 스펙 문서 미수령)
↑ 내부 지연? 외부 블로커?
```

→ **규칙**: 의존성 컬럼 추가 (🟢/🔴/⚫), 외부 의존성 명시
