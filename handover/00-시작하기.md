## 🎯 1차 설계 요약

### 핵심 아키텍처
```
Raw (회의록) → LLM 처리 → Wiki (액션 중심) → 아젠다 생성
```

### 확정된 4가지 원칙
1. **SSOT는 Raw에만** — Wiki는 파생 아티팩트
2. **액션 중심 설계** — 결정/액션/보류로 구성
3. **최소 구조 강제** — 표준 프론트매터만 강제, 본문 자유
4. **파일명 규약** — `YYYY-MM-DD-[회의체명].md`

### 확정된 프론트매터 필드
```yaml
회의일: YYYY-MM-DD (필수)
참석: [이름(역할), ...] (필수)
출처: [출처] (선택)
notion_url: [링크] (선택)
가져온시점: YYYY-MM-DD (선택)
```

### 핵심 결정
- 액션 상태는 **후속 회의록에서만** 변경 (Raw의 [ ] / [x] 체크박스)
- Wiki는 **액션 추출과 추적**에 집중
- Raw는 **표준 프론트매터만** 강제 (팀 부담 최소화)
